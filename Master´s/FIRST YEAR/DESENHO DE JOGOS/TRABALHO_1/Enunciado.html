C1: A Path Through Swarms

Challenge

For this challenge, you are going to explore the race to the end core dynamic (see the Types of Games Cores).

Additionally, your game must adhere to the theme “Swarms” and support one to four players.

Design and Implement a game that:

  • Has a race to the end core dynamics;
  • Is based on the theme “Swarms”;
  • Features one to four players;
  • Respects the course contents.

Make sure that you are following Game Design basics:

  • Think about the player’s viewpoint:
    • What’s this game about?
    • How do I play?
    • How do I win?
    • Why do I want to play?
    • What things do I need to do?
  • Create meaningful decisions:
    • Consider the player’s options.
    • Choices must affect the game’s outcome.
    • Look to keep the player’s mind busy.
  • Consider the core of the game.
    • Set polished core mechanics considering the dynamics and the theme.

If you are stuck in the design process, look at the tips to “Overcome Designer’s Block” in The Basics notes and book chapter.

The game should allow one to four players, be about progressing on a path, and make them go from point A to point B. The first player to get to point B wins.

As the game’s designer, it’s up to you to figure out how to fit the theme, select the gamebits/assets, and the mechanics.

Deliverable

An archive (zip file) with:

  • A beta prototype of the game (All systems have been implemented and all code is theoretically complete. No major bugs are expected.).
  • A concept document of the game (a PDF file) as outlined in the Concept Document Structure chapter of the course notes.

Optional Game Features

“Hard” Mode

Implement an “Hard” Mode where chance against you is higher.

“Easy” Mode

Implement an “Easy” Mode where you have items and mechanics that help you.

“Against The Clock” Mode

Implement a mode with a time limit to achieve intermediate goals.

Other Features

Describe and implement other features, not listed here, that might improve the game experience.

The game has instructions? A tutorial mode? Can it be paused, saved, loaded? The player has some kind of score?

Suggested Process

  1. Determine the goal. Where are the players going, and why are they going there? Choose how the theme involves some interaction between the participants, to make things interesting.

  2. Identify mechanics.

    • Start simple. Visualize a track that goes from beginning to end that’s broken up into a bunch of different sections. It may be 100 spaces or tiles or cards that ultimately build the track on which your players are going to “race.”
    • Now think of the mechanic that will get your players moving on that track. The simplest one is rolling a die.
    • Next consider things you could do to make play more interesting.
    • You could have an action that speeds you up or slows your opponent down. Does the narrative suggest any obvious mechanics?
    • If your game is about a relay foot race, you’ll need a way to pass the baton (perhaps suggesting a tradeoff where maintaining a higher running speed gives a higher chance of accidentally dropping the baton).
    • To add some player interaction in a foot race, perhaps you’d adapt the theme so that the racers are robots with lasers that can shoot at one another, which suggests mechanics for shooting and dodging.

  3. Identify the conflict between players. How can you screw up someone else’s progress or accelerate yours? What’s the tradeoff?

  4. Playtest. Every time you add a mechanic to the game, test it. Does it make the game more fun or less fun? Does it support the core of the game? Does it work the way you originally thought it would?

  5. Create a beta version.
